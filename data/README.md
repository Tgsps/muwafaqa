# Test data

All data in this folder is **entirely fictitious**: fake company names (each carries a "Test" or "Fictional" marker), fake registration numbers (`TEST-CR-####`), emails on the reserved `example.com` domain, invented contract values. Do not replace anything with real data.

| File | Rows | Target table |
|---|---|---|
| `counterparties.csv` | 5 | Counterparty (`mwf_counterparty`) |
| `contracts.csv` | 10 | Contract (`mwf_contract`) |

CSV headers match the schema names in [docs/data-model-phase1.md](../docs/data-model-phase1.md). Choice and Status Reason columns hold **labels**, not numeric values (the numeric values are generated by Dataverse). The Counterparty Lookup holds the counterparty **name**, and the Currency lookup holds the currency **name**.

## Warnings

- **Exchange rates are assumptions**, used for demonstration only. They are not market rates.
- **KWD has 3 decimal places** (ISO 4217); the other currencies here use 2. Two KWD rows use 3 decimals (`6500.250`, `9000.000`). Whether the Value column displays and stores 3 decimals for KWD depends on column precision settings. See the KWD item in [docs/verification-checklist.md](../docs/verification-checklist.md).
- **Turn the approval flow off before importing** (see [docs/flow-approval-v1.md](../docs/flow-approval-v1.md)), and do not change an imported row's Status Reason to Pending Approval while it is on, unless you want to start an approval.

## Prerequisites

1. The solution `Muwafaqa` exists with both tables created per the data model.
2. Currency records exist in the `Currency` table (step 1 below).

## Step 1 — Currency records (manual)

Create or check these rows (Power Platform admin center → environment → Settings → Business → Currencies, or the Currency table). The **Currency Name must match the CSV exactly**, because the Lookup is matched by name.

| Currency Name (CSV value) | ISO code | Exchange rate (assumed, units per 1 USD) | Precision |
|---|---|---|---|
| US Dollar | USD | 1 (base currency) | 2 |
| UAE Dirham | AED | 3.67 | 2 |
| Saudi Riyal | SAR | 3.75 | 2 |
| Kuwaiti Dinar | KWD | 0.30 | 3 |

Notes (**not verified**):
- The base-currency record may already exist with the name "US Dollar". Check its exact name. If it differs, adjust the CSV or the record.
- The direction of the exchange rate (units of currency per 1 USD, so base = value ÷ rate) is the expected convention. Confirm using the exchange rate item in the verification checklist before trusting the base amounts.

## Step 2 — Import counterparties first

The Contract Lookup needs the Counterparty rows to exist, so import in this order.

1. make.powerapps.com → select the dev environment → **Tables** → **Counterparty**.
2. **Import** → **Import data from Excel** (or **CSV**) → upload `counterparties.csv`.
3. Map columns. Each header already equals a schema name, so mapping should be automatic. Check:
   - `mwf_name` → Name
   - `mwf_counterpartytype` → Type (Choice mapped by label)
   - `mwf_commercialregistration`, `mwf_contactname`, `mwf_email` → same-named columns
4. Import and confirm 5 rows.

## Step 3 — Import contracts

1. **Tables** → **Contract** → **Import** → upload `contracts.csv`.
2. Map columns:
   - `mwf_counterpartyid` (Lookup) → map by the **primary name** of Counterparty (`mwf_name`). Names are unique in this data set.
   - `transactioncurrencyid` (Lookup) → map by Currency Name.
   - `mwf_contracttype`, `mwf_direction` → Choice by label.
   - `mwf_signeddate`, `mwf_effectivedate`, `mwf_expirydate` → Date Only. Dates are `yyyy-MM-dd`. Empty Signed Date on Draft and Rejected rows is intentional.
   - `statuscode` → Status Reason by label (see caveat).
3. Import and confirm 10 rows.

Caveats (**not verified**):
- Whether the import mapping UI accepts `statuscode` and sets `statecode` consistently (In Force → Active, Rejected → Inactive). If not, import everything as Draft and set statuses manually afterwards, or use a one-off flow.
- Whether Lookups by name resolve for Currency in the maker import, and how it treats a name that matches more than one row.
- Row owner: with User-owned Contract, imported rows are owned by the importing user.

## Step 4 — Verify

- Counterparty: 5 rows. `Demo Partner Holdings Test Inc` has no contracts on purpose.
- Contract: 10 rows. Open one non-USD row and check `exchangerate` and the base amount, and compare with the table below.
